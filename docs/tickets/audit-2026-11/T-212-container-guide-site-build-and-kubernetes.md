## Problem
1. **The Compose quick start fails on a fresh clone.** `docker-compose.yml` builds the `site` image from
   `site/Dockerfile`, whose line 5 is `COPY public /usr/share/nginx/html`. `public/` is not in git (it is
   generated by `pnpm site-build` and listed in `.gitignore`). `docker compose up -d` stops with
   `COPY public: not found`. The guide never says to build it.
2. **The Kubernetes example names things that do not exist.**
   - `runAsUser: 999` / `fsGroup: 999`: `packages/runner/Dockerfile` creates the `qa` user with
     `useradd --system` and no fixed number, so 999 is a guess.
   - `image: ...qa/runner:latest`: `.github/workflows/deploy.yml` pushes only `qa/runner:$GITHUB_SHA`. No
     `latest` tag is ever pushed.

## Notes
- `pnpm site-build` is a real script in the root `package.json`
  (`pnpm --filter @qa/types run build && pnpm --filter @qa/wizard run build && node scripts/site-output.mjs`).
- Decision: the site image stays single-stage. `deploy.yml` builds `./public` with deploy-time `VITE_*` values
  and a commit stamp before it builds the image; a multi-stage Dockerfile would lose both. Do not edit
  `site/Dockerfile` or `docker-compose.yml`.
- `<uid of qa>` is a placeholder for the reader on purpose. Do not invent a number.
